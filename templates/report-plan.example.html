04 / 06 · PLAN

6개 Phase

archive 정비 → seed 추출 → 골격 → 인터랙션 → 저장 → 검증.

0

Archive

_archive-md/{tasks,history}/ 생성 후 기존 md 이동. 본 task 파일은 유지. 비-md(.json)는 제외.
1

Seed 추출

seed_board_from_md.py가 archive 스캔. id/title/date/category/checklist/body 추출 → board.seed.json.
2

골격

vanilla HTML/CSS/JS 단일 파일. 헤더 + 3 칼럼 + 카드(날짜·제목·진행률바·미리보기). 로드 시 inline JSON을 state로 적재.
3

인터랙션

카드 모달 편집, Drag-and-Drop(진행률 자동화 금지 — 사용자 의도 우선), 카드 추가, 검색 필터. 상태는 state 객체에만.
4

저장

DOM 직렬화 금지 — state를 inline JSON으로 재생성해 새 문서 Blob. 파일명 board.html 고정. 다운로드 후 페이지 유지.
5

검증

44+1 카드 표시, 토글·드래그·추가 동작, 저장→덮어쓰기→새로고침 유지, Console 에러 0.
05 / 06 · RISKS

사전 리스크

Opus(세션 컨텍스트) + Codex(독립 분석) pre-mortem. 핵심은 multi-machine과 inline JSON 안전성.

Codex · 치명

Multi-machine lost update

두 머신에서 각자 편집 후 저장 시 마지막 저장자가 이전 변경 통째로 덮어씀. 단일 거대 HTML이라 git merge 사람 해석 불가. → 명시적 한계로 문서화.

Codex · 보안

Inline JSON escaping / XSS

카드 본문의 </script>·HTML·코드블록이 파싱 깨거나 DOM injection. → 렌더링은 무조건 textContent, seed 단계에서 </script> escape.

Codex · 품질

Diff noise 폭증

토글 빈도↑ → 단일 HTML diff 비대. → inline JSON을 카드 1개당 1줄로 직렬화. 한 카드 변경 = 한 줄 diff. beautify 금지.

Opus · 운영

자동화/메모리 reference 깨짐

cron/dashboard/스크립트가 docs/tasks|history 경로 의존 가능. → Phase -1 의존성 grep 점검 추가. rules/는 archive 제외.

Opus · 일관성

/cp SKILL mixed period

SKILL 미수정 시 새 /cp가 board 아닌 md 생성. → SKILL/CLAUDE.md override를 본 작업에 흡수해 mixed period 0.

Codex · UX

file:// 저장 취약

다운로드 위치 실수, 중복 파일명(board (1).html), 덮어쓰기 누락이 정상 실패 경로. → 저장 토스트로 안내.

06 / 06 · RESUME

재개 포인트

다음 세션 진입 시 여기부터.

archive 정비가 모든 후속 단계의 전제. 의존성 점검을 먼저 통과시킨 뒤 진행.

  1. Phase 0 — archive 이동

    docs/_archive-md/ 디렉토리 생성 후 기존 md 이동. 비-md 산출물은 제외.

  2. Phase 1 — seed 스크립트

    scripts/seed_board_from_md.py 작성 및 1회 실행 → board.seed.json.
단일 정적 + full edit + 디스크 SoT의 paradox는 "다운로드 → 수동 덮어쓰기"로 해소한다.
