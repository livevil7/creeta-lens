# Lens v3.3.0 Roadmap — Cost-aware Orchestrator

## 목표

Lens 의 포지셔닝을 **"task executor"** 에서 **"plan-fidelity + cost-aware orchestrator"** 로 이동합니다. 커뮤니티(superpowers, gstack)가 검증한 패턴 중 Lens 의 약점에 해당하는 부분을 흡수하고, 2026 년에 풀린 Claude 신기능을 실제로 활용합니다.

- [ ] **Plan-drift 방어** — `/cp` 로 만든 계획에서 실행이 이탈하면 즉시 경보 (community issue #32253 의 핵심 페인)
- [ ] **Token / cost 가시화** — Worker 마다 사용 토큰·소요 시간·예상 비용을 PostToolUse(Task) 와 Stop 훅으로 노출
- [ ] **Session title 자동 명명** — UserPromptSubmit 훅에서 `hookSpecificOutput.sessionTitle` 설정
- [ ] **Skill picker 프롬프트 캐싱** — `/c`, `/cc` Leader 의 스킬 선택 컨텍스트를 ephemeral cache 로 90% 비용 절감
- [ ] **`/cs` cost-cap & status** — sync 결과 표에 토큰 비용·repo별 변경 라인 수 표시, push 단계 예산 초과 시 차단
- [ ] **신규 스킬 3종 — `/qa`, `/retro`, `/canary`** — 커뮤니티 검증된 패턴을 Lens 컨벤션으로 흡수

## 기술적 접근

### Plan-drift 방어 (Phase 1)

**왜**: Anthropic 자체 issue tracker 의 #32253 처럼, plan 모드를 빠져나간 후 implementation 이 plan 을 무시하는 사례가 다수 보고됐습니다. Lens 는 `/cp` 로 plan 을 만들고 `/cc` 로 실행하는 두 단계 파이프라인을 권장하지만, 두 단계 사이의 결합이 약합니다. plan_id 를 도입해 plan-state.json 에 활성 계획을 1 개로 관리하고, 모든 실행 hook 이 그 plan 을 기준으로 deviation 을 누적합니다. Supervisor 가 deviation 을 무시하지 못하도록 Phase 4 에 강제 게이트를 둡니다.

**대안 비교**: (a) plan 을 frontmatter 만으로 정적 비교 — 누적 telemetry 없으면 드리프트 발견 시점이 늦어짐. (b) 세션 메모리에 plan 보관 — 멀티 세션 / 멀티 머신 환경에서 깨짐. → **(c) `~/.claude/lens/plan-state.json` 영속화 채택**.

### Cost telemetry (Phase 2)

**왜**: 커뮤니티 데이터에 따르면 49-agent orchestration 이 단일 세션 $8k–$15k 까지 폭주한 사례가 있습니다. Lens 의 `/cc` 가 worker 5 개까지 띄우는데 비용 보고가 0 입니다. PostToolUse(Task) 훅이 이미 등록돼 있으므로 거기에 `usage_input_tokens`, `usage_output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` 4 필드를 누적하기만 하면 됩니다. Anthropic Pricing 표(`claude-opus-4-7` $15/$75, `claude-sonnet-4-6` $3/$15, `claude-haiku-4-5` $0.80/$4 per MTok) 를 `lib/pricing.js` 에 박아 환산.

**캐시 비용 처리**: cache_read 는 base input 의 10%, cache_creation 은 125% 로 환산. 이게 Phase 3 의 prompt caching ROI 를 정확히 반영하기 위해 필수입니다.

### 프롬프트 캐싱 (Phase 3)

**왜**: `/c`, `/cc` Leader 호출은 매 세션마다 동일한 스킬 인벤토리(40+) + 매칭 룰 + 시스템 프롬프트(약 5–8K 토큰) 를 보냅니다. 이 부분을 `cache_control: { type: "ephemeral" }` 블록 1 개로 묶으면 5 분 TTL 동안 90% 할인. 하루 평균 `/c` 5 회 사용한다고 가정하면 단순 추정으로 월 $2–4 절감.

**구현 위치**: `/c`, `/cc` 의 Leader 호출 부분에서 system prompt 를 두 블록(고정 / 가변) 으로 split. 고정 블록에 `cache_control` 부착.

### 신규 스킬 3종 (Phase 5)

**`/qa`**: Playwright MCP 가 이미 사용자 환경에 설치돼 있음(MCP 등록 표 확인). 이걸 Lens 워크플로(Phase 1 분석 → Phase 2 plan → Phase 3 worker → Phase 4 supervisor) 안에서 호출하는 어댑터 스킬을 짜는 것뿐. 처음부터 풀 구현 X — `mcp__plugin_playwright_playwright__browser_*` tool 들을 wrapping 하는 200 줄 SKILL.md.

**`/retro`**: 입력 = `git log --since` + Lens dashboard JSON. 출력 = `docs/history/retros/YYYY-WW.md`. cron 과 결합하면 매주 자동 작성.

**`/canary`**: Playwright MCP + Lens 의 `productionUrl` config. 배포 직후 N 분간 페이지 스냅샷 비교, console 에러 수집.

### 무엇을 **하지 않을지**

- ❌ Batch API 통합 — Claude Code 가 batch API 를 클라이언트로 직접 호출하는 표준이 아직 없음. Stretch.
- ❌ Managed Agents Sessions — 베타 단계, lock-in 위험. Stretch.
- ❌ 자체 plugin marketplace UI — 사용자는 이미 GitHub-marketplace 패턴에 익숙. 기존 방식 유지.
- ❌ 자체 design/branding 스킬 — gstack/ccplugins 가 이미 잘 함. 충돌 회피.

## ⚠️ 사전 리스크

### Claude Opus 관점 (세션 컨텍스트 기반)

1. **Plan-state.json 단일성 충돌** — 여러 프로젝트에서 동시에 `/cp` 를 쓰면 active plan 이 모호해집니다. 해결: plan_id 를 cwd hash + slug 조합으로 내고 `plan-state.json` 을 `{ "<cwd_hash>": {...} }` 맵 구조로. SessionStart 훅에서 cwd 기준 entry 만 로드.
2. **PostToolUse(Task) payload 의 `usage` 가용성 미확정** — Claude Code 가 subagent usage 를 훅에 노출하는지 문서로 단정할 수 없습니다. **사전 검증 필수**: Phase 2 착수 전에 `pre-tool-task.js` 에 `console.error(JSON.stringify(input))` 박아 1 회 dispatch 해 페이로드 schema 확인. 누락 시 Stop 훅 단일 위치에서 세션 합계만 보고 (worker breakdown 포기).
3. **`/qa` 가 superpowers `/test-driven-development` 와 사용자 혼란** — Lens 컨벤션은 "병렬 + 비용 인지" 이므로 `/qa` 는 *Playwright MCP 어댑터* 역할로 한정. SKILL.md description 에 "TDD 자동화는 superpowers 에 위임, 본 스킬은 배포 검증 전용" 명시.
4. **6 Phase 일괄 배포의 폭주 위험** — Phase 1 (drift) + Phase 2 (cost) 가 v3.3.0 의 핵심 가치. Phase 3–5 는 v3.4 / v3.5 로 분할 권장. 그렇지 않으면 dogfood 전 코드베이스 비대화.
5. **Plan-drift 게이트가 사용자에게 짜증 유발 가능성** — drift 가 정상 진화일 수 있는데 매번 막으면 unblocking 비용 증가. 해결: deviation 임계치 (예: 변경 파일 ≥3 개 외부) 넘을 때만 게이트, 그 이하면 footer 에 줄 한 줄 경고만.

### Codex GPT-5.2 관점 (독립 코드 분석)

Codex 미설치 — 단일 모델 pre-mortem 입니다. 별도 머신에서 Codex 설치 시 다음 명령으로 보강 가능: `codex exec --skip-git-repo-check "이 plan 문서의 허점을 200 단어로 분석..."` 후 본 섹션에 추가.
