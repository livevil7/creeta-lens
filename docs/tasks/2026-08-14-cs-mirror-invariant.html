/cs 미러 개편 — "런이 끝나면 클라우드가 곧 최신"을 불변식으로

/cs의 존재 이유는 미러다 — "병합을 하던 뭘 하던 모르겠고, 클라우드에 올려놓고 다른 컴에서 그대로 받는 것"(대표, 2026-08-14). 현행 설계는 PR 의식을 거치며 실패 지점마다 잔여물을 남기고, 그 잔여물을 어떤 런도 회수하지 않는다.

6개 열린 auto/agent PR · 13~28일 방치 (실측)
+ 병합 끝난 브랜치 14개(금일 수동 정리) + 머지 실패 시 reset --hard 유실 기전이 현행 코드에 잔존 + 미병합이 "성공 32/32"에 은닉.

03 / 8 · GOAL

목표 — 사람 언어

  • 어느 컴퓨터에서든 /cs 한 번이면 작업 전부가 GitHub에 있고, 다른 컴퓨터는 받기만 하면 된다.
  • /cs가 만든 찌꺼기(열린 자동 PR·병합 끝난 브랜치)는 다음 런이 알아서 치운다.
  • "성공"은 진짜 깨끗함을 뜻한다 — 올라가다 만 작업이 성공으로 집계되지 않는다.

Done = 아무 레포나 지저분하게 만들고 /cs 한 번 → 다른 컴퓨터 pull만으로 그 작업이 보이고, GitHub에 열린 자동 PR·병합 잔여 브랜치가 없다.

비목표: prune 흡수(자기 sync/ 잔여물만 회수) · task/agent 브랜치 자동 머지(내용 미상 — 보고까지만) · /cp done·/cc 라이프사이클 변경.

04 / 8 · PLAN A

Plan A — 3층 구조

L1 미러 기본
직push 전환
LENS_SYNC_PR 기본 반전(한 글자). 실패 시 로컬에 커밋 잔존 → 다음 런 재시도(자기치유). sync/ 브랜치·머지·reset 자체가 사라짐. gh 무의존.
L2 회수(reconcile)
자기 잔여물
매 런: 열린 sync/ PR 머지+삭제, 병합증명 sync/ 브랜치 atomic 이중 lease 삭제. 미증명은 절대 보존.
L3 불변식 보고
성공 재정의
✅ = local==origin/base ∧ dirty 0 ∧ 열린 sync PR 0. 비-base 작업은 나이와 함께 노출(7일↑ 경고). --json 버그 수정.
예외 게이트
ERP=배포
Returns_ERP_v20은 syncPolicy=pr-manual — PR 생성까지만, 머지는 사람. config+upstream 이름 이중 방어. /cs가 처음으로 lens.config.json을 읽는다.
