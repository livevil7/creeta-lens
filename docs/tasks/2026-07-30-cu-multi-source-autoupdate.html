03 / 06 · GOAL

목표 — 무엇이 가능해지는가

한 번 치면 다 보이고, 안전한 건 알아서 올라가 있다. 위험한 것만 사용자가 판단한다.

종류를 가리지 않는 한 목록 — 명령줄 도구든, 설치된 프로그램이든, 편집기 확장이든, 클로드 플러그인이든 업데이트 가능한 것이 빠짐없이 한 표에 뜬다.
고르지 않아도 끝나 있다 — 항목을 하나하나 선택하는 절차가 사라진다. 되돌리기 쉬운 것은 묻지 않고 최신으로 올라간다.
위험한 것은 따로 모인다 — 데이터베이스·언어 런타임·시스템 구성요소·큰 버전 점프는 자동으로 건드리지 않고, 왜 보류인지와 직접 실행할 명령이 함께 나온다.
버전 표시를 믿을 수 있다 — "버전 모름"으로 비거나, 최신인데 업데이트가 있다고 잘못 알리는 일이 없어진다.

지금 (Done 아님)

표에 10줄. winget·npm·확장은 존재조차 안 보임. 업데이트가 있으면 매번 골라달라고 물음. agentmemory는 최신인데 ⚠️, context7은 ❓.

Done = ?

소스별로 빠짐없이 표에 나오고, 아무것도 선택하지 않았는데 안전한 항목은 이미 최신. 손대지 않은 항목은 사유와 명령이 함께 적혀 있다.

04 / 06 · PLAN

Plan A — 소스 단위 스캐너 + 위험도 자동 분류

도구를 등록하지 않는다. 패키지 매니저가 이미 아는 것을 물어본다. 질문은 없애고 판단은 정책으로 남긴다.

T0

테스트 먼저 (fixture)

실제 winget 출력을 캡처해 fixture로. 손 타이핑 금지. 4개 불변식: 표 파싱 · semver↔SHA 금지 · 3단 분류 · dedup. 구현 전엔 실패해야 한다.
T1

스캔 계약 확장

항목에 source·risk·hold_reason 추가. 출력을 {items, source_errors} 객체로. 종료코드 규약은 불변.
T2

플러그인 버전 해석 수정

마켓 클론의 <source>/.claude-plugin/plugin.json을 읽는다 (핵심). unknown이면 gitCommitSha 사용. 형태 불일치 → None.
T3

winget 스캐너

헤더 위치로 컬럼 경계. id 컬럼만 신뢰(이름은 폭에 따라 잘림). 비승격일 때만 --scope user 교차 확인.
T4

npm · VS Code · pip

npm은 outdated -g --json. VS Code는 --update-extensions 1회 + 전후 diff. pip은 집계 한 줄(never).
T5

dedup · 정책 상수 · 스냅샷

같은 도구 두 줄 방지(cli:claude vs npm). 정책을 상단 상수 3개로. 실행 직전 스캔을 cu-last-scan.json에 저장.
T6

SKILL.md 재작성 [P]

AskUserQuestion 삭제. 3모드 표. 재스캔 규칙 교체(전체 1회 필수). 실행 전 예고 의무.
T7

실측 전수 검증

순서 고정: 분류가 옳음을 먼저 증명한 뒤 실제 업그레이드. 뒤집으면 검증이 사고가 된다.
T8

출시 v3.26.0

bump-version.sh 14곳 → CHANGELOG → 커밋 → 태그 → push → git show 확인. 태그 누락 = 옛 코드 설치.

위험 등급 3단 — 무확인 실행의 경계선

auto (묻지 않고 실행): 플러그인 전부 · npm patch/minor · 나머지 winget.
hold (/cu all로만): 메이저 점프 · 런타임(Node·Python) · 시스템 구성요소 · 승격 필요.
never (/cu all에도 제외): DB(PostgreSQL 등) · 드라이버 · winget 자신 · pip 글로벌.

Plan B — 안전한 쪽으로 떨어진다

winget 파싱이 깨지면 id 단위 조회(B1) → 안 되면 보고 전용(B2, "19건 대기" 가시성만). UAC로 멈추면 30초 선행 시험 후 winget 전체를 hold로 강등(B3). 커버리지를 줄이는 방향이라 실패해도 사고가 아니다.

05 / 06 · RISKS

사전 리스크 — Codex 교차검증 + Pre-mortem

Codex 분기 6건은 전부 코드로 재확인해 Codex 채택. Pre-mortem 10건 중 7건을 계획에 반영했다.

P1 · data loss · 최고

/cu all이 데이터베이스를 자동 업그레이드

hold 전량 실행 설계였는데 hold에 PostgreSQL이 있었다. DB 업그레이드는 데이터 디렉터리 마이그레이션을 유발할 수 있고 되돌릴 수 없다. "all을 쳤으니 승인"은 오타 한 번을 정당화하지 못한다. → never 3단계 신설. 테스트가 /cu all 대상에 never 부재를 단정.

Codex 분기 1 · 정확성

오탐이 1건이 아니라 2건

Claude는 agentmemory만 봤고 Codex가 insane-search를 추가 지적. 재스캔 결과 installed=0.13.0 latest=687824e6 needs_update=True — 오늘 오전 올린 직후인데 또 업데이트 요구. Codex 지적이 정확했다.

P2 · 테스트 무효화

fixture를 손으로 쓰면 테스트가 헛돈다

사람이 타이핑하면 실제 컬럼 폭·공백 수를 못 맞춘다. 테스트는 통과하는데 실물에서 깨진다 — 최악의 조합. → 실제 출력 캡처만 허용, 손 작성 금지를 T0에 명시.

R2 · P3 · 실측 확인

비승격 셸 + winget = UAC 멈춤 / 이름 잘림

현재 셸이 NOT_ELEVATED로 확인됐다. 머신 스코프 패키지를 올리려 하면 실패하거나 UAC로 멈춘다. winget은 콘솔 폭에 맞춰 이름을 자르기도 한다. → id 컬럼만 신뢰 + 비승격 시 --scope user 교차 확인 + B3 선행 시험.

Codex 분기 3 · 채택

테스트를 먼저 쓴다 (TDD)

Claude는 실측 검증만 계획했다. Codex가 fixture 단위테스트 선행을 제안 — 사용자 4규칙의 TDD 우선과 맞고, 레포에 이미 관행(lib/install-sync.test.js)이 있다. 실측만으로는 이 컴퓨터에 안 나타나는 케이스를 영원히 못 잡는다.

P4 · P5 · P6 · 반영

보고 도배 · 파일 충돌 · 중복 호출

pip 수십 건이 hold 목록을 뒤덮어 PostgreSQL을 묻는다 → 집계 한 줄. T3·T4가 같은 cu.py를 병렬 수정 → 직렬화. winget 2회 호출 → 비승격일 때만 scope 조회.

Codex 분기 4 · 부분 채택

/ci와 버전 해석이 어긋날 수 있다

lib/install-sync.js:161에 cu.py fallback path 주석이 실재 — 같은 레지스트리를 파싱한다. 다만 Node ↔ Python이라 코드 공유는 프로세스 계층만 늘린다. → 규칙만 일치시키고 파일은 수정하지 않는다(어긋나면 후속 태스크로 분리).

P8 · P9 · 수용

수용된 한계

VS Code 집계 항목은 최신 여부를 모르므로 매 실행 no-op 재설치가 돈다(수 초, diff 0건으로 정직 보고). Teams 같은 날짜형 빌드번호는 메이저 점프로 오분류돼 hold — 과보수 방향이라 안전.

계획 → 병렬 실행 → Codex·Supervisor 더블 게이트 → 수정 → 실측 → v3.26.0 출시. Plan B 전환 없음(W1~W4 미발동).

  1. 조사 — 실측 + Codex 병렬

    winget 19 · npm 6 · 비승격 확인. 오탐 원인 확정(마켓 manifest에 version 필드 없음 → HEAD SHA fallback). Codex 분기 6건 전부 코드 재확인 후 Codex 채택.

  3. 더블 게이트 — 결함 14건

    Codex(2라운드) + Supervisor가 never가 문서로만 막혀 있고 코드로는 열려 있다는 최상위 결함을 독립적으로 지목. upgrade_targets는 실행 흐름이 경유하지 않는 죽은 방어선이었다. fail-open·스냅샷 파괴·/cu scan이 실제 업그레이드·소스 실패 은폐 등 전부 수정.

  4. 실측 검증 (T7)

    auto 9건 실제 업그레이드(winget 5 + npm 4). hold 14 · never 3 버전 불변 확인. cu.sh upgrade winget:PostgreSQL... → 실행 없이 exit 3. msstore 일시 장애(0x8A15003B)와 HRESULT 마스킹 함정을 실측으로 발견해 수정.

  5. 출시 — v3.26.0 (T8)

    버전 44곳 + CHANGELOG + 커밋 → 태그 → push. 마켓플레이스 source.ref가 태그를 보므로 순서 엄수.
