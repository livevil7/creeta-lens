03 / 06 · GOAL

목표 — 무엇이 가능해지는가

새 모델이 나와도 문서를 사람이 고치지 않는다. 항상 그 시점의 1등 두뇌로 일한다.

난이도 배분 + 자동 추종 — 모든 일꾼이 업무 난이도에 맞는 등급의 모델로 일하되, 가장 어려운 업무는 항상 그 시점의 최고 모델. 새 모델이 나와도 문서 수정 없이 사다리가 자동 상승.
오늘 기준 실증 — Hard 업무가 fable로, codex가 gpt-5.6-sol로 실제 실행되는 것을 명령으로 확인. Easy/Medium은 haiku/sonnet 유지.
조용한 강등 금지 — 예비 경로(fallback)로 낮은 모델로 넘어가면 반드시 결과물에 ⚠️ 표시가 남는다.
자기 감시 — 모델 순위가 바뀌어 문서 예시가 낡으면 Lens의 정기 감사(/crv)가 스스로 알아차린다.
출시 완결 — v3.24.0으로 태그까지 출시되어 이 컴퓨터에 반영. (다른 컴퓨터는 각자 업데이트 시 자동.)

runtime · blocker → 해소

빈 값이 -m ""으로 새는 조용한 강등

순위표가 비거나 파일이 없으면 resolver가 빈 문자열 → 그대로 전달 시 조용히 기본 모델로 실행. → 인자 배열 분기 + 명시적 exit + 플래그 echo로 원천 차단. 성공/실패 경로 실측 완료.

deploy · high

커밋 전 태그 = 옛 ref를 가리키는 출시 사고

marketplace가 태그의 ref를 보고 설치 — 순서가 바뀌면 다른 컴퓨터에 옛 코드 설치(실제 사고 이력). → 커밋→태그→push→git show 검증 순서 엄수 절차화.

design · high

세션이 낮은 모델이면 상속이 품질을 낮춤

상속 규칙만 있으면 sonnet 세션에서 일꾼도 sonnet. → TOP 정의에 판정 절차 명시: 세션 ≥ 목록 최상위면 상속, 미만이면 최상위 명시 지정.

design · 수용된 한계

미래 새 모델명의 우열은 자동 판별 불가

Claude 두뇌 목록에는 순위 정보가 없다. 완전 자동 보장은 불가 — 판별 불확실 시 상속이 안전 기본값 + /crv 감사가 목록 변화를 감지해 개정 제안.

deploy · high

capability-assumptions.json을 라인 편집하면 /crv 전체가 죽을 수 있다. → Edit 정밀 교체 + node 파싱 검증(exit 0) 의무.
