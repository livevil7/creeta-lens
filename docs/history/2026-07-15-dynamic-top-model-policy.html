03 / 07 · PROBLEM

왜 했나 — 이름을 못박으면 세대가 바뀔 때 낡는다

Before

지시문에 opus·gpt-5.5 가 문자열로 박혀 있었다. 최고 난이도 업무(설계·검토·검증)가 한 세대 전 두뇌로 돌고, codex 검증 파트너는 순위표 7위 모델이었다. 새 모델이 나오면 사람이 문서를 찾아 고쳐야 했다.

After

사다리의 칸을 상대 위치로 정의했다 — 경량 / 중간 / enum 최상위. codex 는 순위표 1등을 매 호출 직전 동적 선택. enum·순위표가 갱신되면 배분이 따라 올라간다.

사용자 정정 (2026-07-15 Modify)

"최고 모델 무차별 배정"은 목표가 아니었다

초안은 Claude 축을 "전 역할 TOP"으로 잡았다. 사용자 지적 — 원칙은 난이도별 배분이고, 사다리의 각 칸이 모델 세대와 함께 자동 상승하는 것이 이 작업의 본질이다. 이 정정으로 /cc 의 v3.11 "전부 opus(품질 우선·비용 비고려)" 철학이 공식 폐기되고 /c 와 사다리가 통일됐다.

04 / 07 · DECISIONS

주요 결정

난이도 배분이 원칙, 자동 상승이 본질

Easy=경량 티어 / Medium=중간 티어 / Hard=최상위 티어(TOP). 이름(haiku/sonnet/fable)을 적는 대신 상대 위치로 정의해, enum 이 갱신되면 사다리가 따라 올라가게 했다.

codex 는 순위표 1등 동적 선택 — 모델과 깊이를 분리

~/.codex/models_cache.json 에서 priority 최소 slug 를 매 호출 직전 뽑는다. 특정 모델명을 문서에 못박지 않고, 사용자가 데스크톱 앱에서 바꾼 config 기본값에도 의존하지 않는다. 추론 깊이(xhigh/high)는 별개 다이얼로 유지.

조용한 강등 금지

resolver 실패로 낮은 모델로 떨어지면 결과물에 ⚠️ 플래그를 남기도록 의무화했다. 빈 값이 -m "" 으로 새어 조용히 기본 모델로 실행되는 경로를 인자 배열 분기로 원천 차단했다(성공/실패 경로 양쪽 실측).

자기 감시 배선

모델 순위가 바뀌어 문서 예시가 낡으면 Lens 정기 감사(/crv)가 스스로 알아차리도록 capability-assumptions.json 에 감사 항목을 넣었다.

수용된 한계

미래 새 모델명의 우열은 자동 판별 불가

Claude 두뇌 목록에는 순위 정보가 없다. 완전 자동 보장은 불가능하므로 판별 불확실 시 상속을 안전 기본값으로 두고, /crv 감사가 목록 변화를 감지해 개정을 제안하게 했다.

이후 폐기됨 (v3.25.0)

그 "상속" 규칙 자체가 문제였다

지정을 생략하면 훅이 실제 실행 모델을 관측할 수 없어 계측에 구멍이 생기고, 세션이 최상위 모델일 때 모든 Hard 역할이 자동으로 최상위를 먹었다. v3.25.0 에서 상속을 폐기하고 모든 spawn 이 모델을 명시하게 바꿨다 — 명시하면 기록되고, 기록되면 통제된다.
