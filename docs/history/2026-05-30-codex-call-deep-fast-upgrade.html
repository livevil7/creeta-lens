03 / 08 · PROBLEM

문서가 실제와 어긋나고, 호출이 얕고 깨졌다

문서엔 GPT-5.2 표기가 남아 있었고, 응답은 취약한 텍스트 awk로 긁어 깨졌으며, 숫자 timeout이 background 병렬 호출과 모순이었다.

05 / 08 · KEY DECISIONS

왜 이렇게 결정했나

SoT 단일화 · 깊이/속도 우선 · timeout 폐기 · race 방지 · opus 상향 · 죽은 설명 강등.

01

SoT 단일화 (Plan A)

호출·파싱·에러처리를 codex-integration.md 한 곳에서만 고치고 SKILL.md는 "§N 참조"로 통일. 외과적이고 버전 전파는 bump-version.sh가 11곳 일괄 처리.

02

깊이·속도 우선 (비용 비고려)

gpt-5.5 + xhigh + priority + -o로 고정. priority는 부하 시 큐 우선권일 뿐이라고 명시해 "빨라진다" 오해 차단.

03

숫자 timeout 폐기

background 병렬이라 느려도 기다리지 않는다. hang해도 Claude를 막지 않으며 세션 종료(Stop 훅)가 orphan 정리 → 숫자 timeout 불필요.

04

-o 파일명 race 방지

Phase 0.5·2.4·4.5가 병렬이라 같은 임시파일 덮어쓰기 위험. /tmp/codex_<phase>_<rand>.txt 고유 파일명을 §5 표준으로 박음.

05

Claude 역할 opus 상향

Worker(Easy/Medium/Hard)·Supervisor·QA를 모두 opus로. Monitor만 haiku — 상태 폴링만 해 opus 품질 이득 0인 유일 예외.

06

죽은 설명 강등

-o로 본문만 받으면 §5 "원본 출력 예시"가 추출에 안 쓰임. 삭제 대신 "참고용 — 추출은 -o 권장"으로 강등해 오해 방지.

06 / 08 · VALIDATION

됐다는 증거

검증표 7개 중 자동 판정 5개 전부 통과. degrade는 작업 중 실증됐고 배포·설치까지 확인.

자동 grep 판정 + 실호출 degrade 실증 + 배포/설치 확인의 3중 검증.

  1. 표준 호출 + 잔재 0건 (#1·#2·#3)

    표준 호출에 -m gpt-5.5·xhigh·priority·-o 전부 존재. 세 파일 활성 코드에 tokens used·awk '/^codex/'·timeout 30 0건, 모델 5.2 지칭 0건.

  2. 모델 배정 (#6·#7)

    cc/SKILL.md에서 Worker/Supervisor/QA = opus, Monitor = haiku 표기 확인. cp/SKILL.md Phase 3.1 pre-mortem은 opus 유지(다운그레이드 없음).

  3. degrade 실증 (#4)

    Phase 0.5 Codex 조사가 sandbox 차단 + 한글 mojibake로 degrade → Claude가 -o 동작을 직접 실측(본문만 파일로 떨굼 확인)하며 단독 완료. 본 작업이 인코딩하려던 graceful degrade의 실증.

  4. 배포 · 설치 (#5)

    commit b7c195f + tag v3.11.0 push(livevil7/creeta-lens = CreetaCorp/lens). scripts/upgrade.sh로 캐시 3.11.0 설치, plugin list v3.11.0 확인.
