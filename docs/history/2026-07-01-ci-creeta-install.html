04 / 07 · KEY DECISIONS

왜 이렇게 설계했나

파괴적 연산 안전이 최우선. Codex 교차 협의가 안전모델과 참조 패턴을 교정.

01

managed / excluded / foreign 3분리

제거는 manifest.excluded 명시 항목만. 목록에 없는 foreign은 절대 자동 삭제 없이 보고만. 모든 uninstall은 백업 + 항목별 승인 뒤. (Codex 핵심 교정)

02

Lens 자기보호 하드가드

lens@CreetaCorp는 제거 후보에서 원천 배제 — self-uninstall 재앙을 Constitution 레벨에서 차단.

03

cu.py 패턴 재사용

초안의 모델 install-skills.ps1은 이 레포에 없음(Codex 지적으로 확인) → 레포 내 scripts/cu.py의 installed_plugins.json 직접 읽기 + scope 보정 패턴으로 교체.

04

설치현황 이중 수집

claude plugin list --json 1차 + installed_plugins.json 폴백 — CLI 스키마가 버전 따라 변할 수 있어 폴백 필수.

05

범용 설계 (내 전용 아님)

livevil 개인 특화 로직 금지. manifest는 사용자가 채우는 빈 틀로 시작 — Lens를 쓰는 누구나 자기 목록을 갖는다.

05 / 07 · VALIDATION

어떻게 믿을 수 있나

사후 아카이브 — 당시 개별 검증 로그는 없다. 대신 릴리즈 산출물과 현재 상태로 확인.

EARS 6건 중 auto 항목은 단위테스트가 커버하도록 설계.

  1. 단위테스트 설계 (EARS auto)

    lib/install-sync.test.js — foreign 불가침(toRemove 절대 미포함) · lens 자기보호 · excluded∩installed 케이스. 레포에 실존.

  2. 검증 로그 부재 (정직 명시)

    이 문서는 사후 아카이브 — 당시 dry-run·백업 확인 로그는 남아 있지 않다.

  3. v3.22.0 릴리즈·설치로 최종 확인

    산출물 3종이 레포에 실존하고, /ci가 세션 스킬 목록에 정상 노출 (2026-07-04 확인). tag v3.22.0 · commit fe20cb2.
