03 / 08 · PROBLEM

계획서는 받았는데, 결국 되묻게 된다

기존 /cp는 가벼운 계획에 좋다. 그러나 실전 요청을 구현으로 넘기면 "이건 어디에? 빈 화면은? 에러는?" 같은 되묻기가 남는다.

Before

/cp standard plan

목표가 기술 용어로 흐려지고, UI 요청도 일반 체크리스트로 평탄화. 구현자가 화면 상태·문구·파일별 변경을 다시 물어야 한다.

Codex 교차 검토가 선택적이라, 협의 없이 조용히 진행될 수 있다.

After

/cpp power plan

맨 앞에 "이게 끝나면 무엇을 할 수 있나"를 사용자 언어로 박고, UI면 ASCII 와이어프레임+요소스펙+상태+문구까지 그린다.

Codex 교차 협의가 양보 불가로 거쳐지고, 미감지 시 정지·보고. 새 세션이 추가 질문 0회로 그대로 구현 가능.

04 / 08 · PIPELINE

9스테이지가 하는 일

고정된 spine은 목표·Constitution·검증·실행·진행상황뿐. 나머지는 주제가 구조를 정한다.

S0

Goal Locked

🎯 목표 + 🎬 사용 장면 + 📜 Constitution을 LOCKED로 박는다. 목표는 사용자 언어, 기술 토큰 0.

S1–S2

Clarify & Fan-out

모든 모호함을 사전 해소([?] 0 게이트). 이어 6축 병렬 조사를 Task 도구로 동시 수행.

S3–S4

Deep Spec & Codex

도메인 라우터로 body-adaptive 딥스펙(UI→ASCII 와이어프레임). 이어 Codex 교차 협의를 하드게이트로 통과.

S5–S8

Tasks → Handoff

빌드레디 태스크(경로+변경+검증+[P]+의존, 10–20분) → EARS 검증 → self-check → /cc 핸드오프 + /goal 라인.

05 / 08 · KEY DECISIONS

왜 이렇게 설계했나

spine 4조항(Constitution)이 양보 불가 원칙을 잡고, 벤치마크 3종이 검증된 패턴을 댄다.

01

/cp 무수정 · 신규 폴더 격리

가벼운 계획은 /cp, "끝장 계획"은 /cpp로 역할 분리. Surgical — /cp·lib/*·기존 skill 0줄 수정.

02

Codex 교차 협의 = 하드게이트

graceful-degrade 금지. Codex 미감지 시 조용히 진행하지 않고 정지·보고. 단 일시 다운(R2)을 위해 1회성 명시 우회 문구 보존.

03

Goal-Locked (사용자 언어)

목표 문장에 함수/HTTP/SQL/경로 등 기술 토큰 0개 강제. 약한 목표는 승인 거부(/cp v3.8 계승).

04

Body-Adaptive 구조

spine 외 의식적 섹션 금지. 도메인 라우터로 UI는 ASCII 와이어프레임+요소스펙+상태, API는 계약서를 산출.

05

벤치마크 3종만 채택

Spec Kit(Constitution/clarify/analyze) · Kiro(EARS/waves) · Superpowers(빌드레디 포맷). BMAD 다중 페르소나·별도 CLI·7-커맨드 분리는 과함으로 미채택.

06

깊이 ≠ 장황 (R1)

power가 토큰 폭발로 변질되지 않게 TL;DR 의무화 + "불필요 섹션 금지" 게이트를 SKILL.md에 명시. 깊이는 정보 밀도지 분량이 아니다.

  3. Codex 게이트 · 회귀 0

    Codex 미감지 시 진행 정지·보고를 SKILL.md에 명시. /cp·board·/cc 핸드오프 회귀 0 점검.
