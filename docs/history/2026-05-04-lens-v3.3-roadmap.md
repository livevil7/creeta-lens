# Lens v3.3 Roadmap — 부분 달성, 재정렬 필요

**완료일**: 2026-05-14

## 요약

5/4에 작성한 6-phase 야심찬 로드맵(Cost-aware Orchestrator). 실제로 release된 v3.3.0(`ee1a4f9`)은 로드맵 범위와 다른 방향 — **source-format fix + bump-version.sh hardening**이 핵심이고, 로드맵의 plan-drift/cost telemetry/prompt caching/`/cs` 강화/`/qa`·`/retro`·`/canary` 신규 스킬은 **모두 미착수**.

|-------|------|-----------|
| 1. Plan-drift | ❌ 미착수 | — |
| 2. Cost telemetry | ❌ 미착수 | — |

## 주요 결정 사항

- **로드맵 우선순위 재조정 필요**: 5/4 작성 후 2주 동안 실제 사용자 페인이 hook stability + plugin source format 쪽으로 드러남. 로드맵의 Phase 1-5는 가치 있지만 우선순위가 아님.
- **v3.3.0 release scope 축소 채택**: 로드맵 따라가지 않고 실제 발생한 lookup-fail 패턴 + bump-version 버그 fix에 집중. 작은 release를 자주 내는 패턴이 더 안전.
- **로드맵 carry-over**: 6 phase 모두 미착수 → v3.4 또는 v4.0 roadmap으로 이관 권장.

## 추가 사항

### v3.4 또는 v4.0 후보 항목 (carry-over)

- **plan-drift 방어**: `/cp` plan_id + `~/.claude/lens/plan-state.json` 영속화 + Supervisor 강제 게이트
- **cost telemetry**: `lib/usage-meter.js` + `lib/pricing.js` + PostToolUse hook에서 worker별 토큰 누적
- **prompt caching**: `/c`, `/cc` Leader 호출에서 system prompt를 ephemeral cache block으로 분리 (5분 TTL, 90% 할인)
- **`/cs` 강화**: cost-cap, `--cost-preview`, status, AUTO_COMMIT_BLOCKLIST
- **`/qa`, `/retro`, `/canary` 3종**: 커뮤니티 검증 패턴 흡수

이 carry-over 5개는 v3.4 roadmap task로 새로 작성 권장. 이번 history 종결 시점에는 미착수 상태 명시로 충분.

### lens-qa-review의 CRITICAL 2건과 통합 고려

QA review에서 미해결 처리된 stdin blocking + fs try/catch 2건은 hook stability 영역. v3.4의 Phase 1(plan-drift)과 hook 변경이 겹치므로 묶어서 처리 가능.
