03 / 08 · PROBLEM

왜 지금 감사가 필요한가

네이티브 4종이 /c·/cc·/cp의 절차 대부분을 prose 래퍼로 만들었다.

네이티브가 흡수한 "엔진"

Dynamic Workflows(16동시·adversarial verify, v2.1.154+) · per-agent 모델 서브에이전트 · /goal(매 턴 Haiku 평가자, v2.1.139+) · plan mode. /cc 병렬 팬아웃, /c Supervisor·QA·5회루프, /cp 목표강제·프리모템이 여기 겹친다.

그래도 OBSOLETE 0인 이유

네이티브는 전부 세션 휘발성(디스크 산출물 없음), 단일 Anthropic 모델 가족(cross-vendor 검증 불가), Karpathy 계약 미강제. 이 셋이 Lens 코어를 살린다.

05 / 08 · CORES

살아남는 코어 3 + KEEP 2

엔진은 네이티브에 위임해도 이 셋은 구조적 비대체.

① 디스크 영속 산출물 — /cp board HTML·docs 라이프사이클, /cps 라우팅 인덱스, 감사로그. 네이티브는 전부 세션 휘발.
② cross-vendor 이종검증 — codex/gpt-5.5. 네이티브 평가자·워커가 전부 Anthropic([sonnet,opus,haiku] 닫힘) → 단일가족 편향을 못 깸. KEEP.
③ Karpathy 4규칙 강제계약 — 전역 CLAUDE.md가 요구하는 사용자-필수 계약을 Worker 프롬프트에 박음.
/cs 멀티레포 sweep — 네이티브 EnterWorktree는 단일레포 멀티워크트리뿐. 워크스페이스 전 레포 fetch+pull+commit+push는 무대체. KEEP.
