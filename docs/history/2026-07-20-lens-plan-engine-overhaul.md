## 요약

계획 엔진을 네 갈래로 개편했다. **세 문제의 뿌리가 하나였다 — 정책은 산문으로 선언되고 강제하는 코드가 없었다.**

1. **기획서 골격** — 비목표·검토된 대안·DO NOT CHANGE·리스크 레지스터·미해결 질문을 필수 섹션으로 추가하고, 등급을 분량이 아니라 **위험도**로 정하게 바꿨다.
2. **실행 진입 게이트** — 얕은 계획으로는 `/c`·`/cc` 가 실행을 거부한다. 검사를 **작성 시점이 아니라 실행 시점**에 뒀다.
3. **모델 배분 통제** — 상속 폐기(모든 spawn 이 모델 명시), 연쇄 승격 폐기(위험도 기반), TOP 상한 도입, 훅 계측 추가.
4. **`/cs` PR-only** — 기본 브랜치 직접 push 폐지.
5. **`/cpp` 폐지** — `/cp deep` 등급으로 흡수.

착수 근거: 산출물 **80건 전수조사** 결과 NFR·인수기준·미결질문·테스트케이스가 **0/80**, 필수라고 선언된 섹션조차 존재율 **28%**. 업계 표준 리서치(PRD·Google DD·RFC·KEP·ADR·PR/FAQ·Spec Kit·Kiro·EARS·ISO 25010) + Codex 교차 협의 + 적대적 검증 2건으로 설계를 굳혔다.

## 주요 결정 사항

- **검사를 실행 시점으로 이동** — 작성 시점 검사는 우회 경로가 많다(다른 쓰기 경로·파일 없는 계획·외부 수정·과거 버전 문서). 실행 진입은 우회할 수 없으므로 레거시 문서까지 자동 커버되고 소급 정리가 불필요해진다.
- **등급은 위험도로 정한다** — 줄 수·페이지 수로 등급을 정하면 길이가 품질의 대리값이 되어 내용 없는 문서가 길이만으로 통과한다. 기준은 "되돌리기 얼마나 어려운가".
- **`/cs` auto-merge → PR-only 로 축소** — 당초 사용자 선택은 "PR + 자동 머지"였으나 Codex 협의에서 *"auto-merge 가 즉시 실행되면 PR 은 검토 단계가 아니라 기록용 포장"* 이라는 반박이 나와 사용자 재확인 후 축소했다. auto-merge 는 비목표로 분리.
- **PR 흐름의 순서가 핵심** — **커밋 전에** 브랜치를 만든다. 기본 브랜치에 먼저 커밋하고 그 브랜치를 push 한 뒤 PR 을 만들면 비교할 변경이 남지 않아 PR 자체가 불가능하다.
- **fail-closed** — `gh` 부재·PR 실패 시 기본 브랜치 직접 push 로 우회하지 않는다. 우회하면 사용자가 요구한 "PR 보장"이 조용히 무너진다.
- **모델 상속 폐기** — 지정을 생략하면 훅이 실제 실행 모델을 관측할 수 없어(`tool_input.model` = undefined) 계측에 구멍이 생기고, 세션이 최상위 모델일 때 **모든 Hard 역할이 자동으로 최상위를 먹는다**(실측된 과소비 원인). 명시하면 기록되고, 기록되면 통제된다.
- **연쇄 승격 폐기** — 종전 규칙은 "TOP worker 가 하나라도 있으면 Supervisor·QA 도 TOP"이었다. Hard 1개 + Easy 3개인 실행에서도 최상위 모델 2개가 추가로 붙었다. 리뷰 깊이가 실제로 필요한 것은 "worker 가 똑똑했을 때"가 아니라 **"틀렸을 때 손해가 클 때"** 다 — 기준을 티어 대칭에서 위험도로 옮겼다.
- **미해결 질문은 "차단만 0"** — 전량 0 을 기계적으로 강제하면 모델이 불확실성을 드러내는 대신 **임의 가정을 확정처럼 기록**한다. 질문 은폐를 유도하는 역효과라 비차단 질문은 가정·확인시점과 함께 남기게 했다.
- **`/cpp` 통합 순서 재배치** — 적대적 검증 2건이 "품질 문제 해결 전 인터페이스 변경"이라며 보류를 권고했다. 폐지 자체는 사용자 결정대로 진행하되 **골격 통일 이후로 순서를 옮겨** 위험을 해소했다.
- **deep 본문 분리(`deep.md`) 기각** — 파일 비대화 방지 목적이었으나 정책은 인라인에 남겨야 하므로 오히려 커진다는 반박이 성립. 통합으로 중복이 소멸해(-154줄) 애초에 문제가 아니었음이 확인됐다.

**유실 1건 — 복구하지 않고 폐기.** 설계 워크플로(3축×3렌즈) 오케스트레이션이 사망했다(`journal.jsonl` 미생성). 복구 대신 폐기를 택했고 Codex 협의가 커버 범위를 대체했다. **이 실패가 진행보고 규약 강화의 직접 원인이다** — 기존 v3.16 규칙이 Workflow 도구를 누락하고 생존 확인을 요구하지 않아 "조용한 사망"을 못 잡았다. `harness-rules.md` §4.4 를 SoT 로 신설하고 6개 스킬에 인라인해, **생존 확인 의무(추측 금지)·끝난 것/남은 것·부분 산출물 선공개** 3항을 필수로 만들었다. "아직입니다"만 적는 보고는 위반이다.

**계획에 없던 작업 1건** — `skills/cpp/SKILL.md` 삭제로 릴리스 스크립트가 깨져 `bump-version.sh` 를 12파일 기준으로 정정해야 했다.

**타임아웃 규칙 개정** — 실측 실패 2건(2026-07-15 대형 diff 리뷰, 2026-07-20 계획엔진 협의)이 모두 180초 상한에 걸려 죽었고, `-o` 부분 수거가 불가능함(0바이트)이 확인됐다. 두 사례 모두 "작업이 클수록 교차검증이 사라지는" 방향이라, 하드게이트가 가장 필요한 순간에 정확히 무력화됐다. 깊이만 규모에 맞추고 시간을 안 맞춘 것이 설계 결함이었다 — 규모 분기(180/300/600초) + 대규모 background 필수로 개정했다.

**되먹임 고리 신설** — 핸드오프에 NON_GOALS·DO_NOT_CHANGE·REJECTED_ALTERNATIVES·BLOCKING_QUESTIONS·GRADE 를 추가하고 **worker 프롬프트에 실제 주입**하게 했다. 계획서에 적어놓고 실행자에게 넘기지 않으면 그 판단은 버려진다 — DO NOT CHANGE 가 없으면 worker 가 무관한 코드를 "개선"하고, 비목표가 없으면 범위를 넘고, 기각된 대안이 없으면 이미 버린 접근을 다시 시도한다. 여기에 편차 기록(계획↔실제)과 실행 지표(추가 질문 수·편차 건수)를 더해 `/cp → /cc → ???` 로 끊겨 있던 고리를 닫았다.
