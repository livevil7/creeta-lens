03 / 08 · PROBLEM

기능이 "여전히 유효한가"를 아무도 묻지 않았다

Claude/Codex의 네이티브 능력은 계속 발전한다. Lens 기능이 메우던 공백이 조용히 닫혀도 알 길이 없었다 — 더 얇아질 수 있는 기능, 무의미해진 기능, 새로 필요한 기능.

Before

드리프트 무감지

네이티브가 따라잡아도 Lens 기능은 그대로 남는다. "지금도 유효한가 / 더 얇게 만들 수 있나 / 무의미해졌나"를 1회성 수작업으로만 알 수 있었다.

반복 비용이 커서 재도출이 매번 처음부터. 일관성도 없음.

After

/cr 한 명령 → 분류 리포트

레지스트리(공백 가정) ↔ 라이브 신호(네이티브 현재 능력)의 diff로 매 감사가 재도출이 아니라 대조가 된다 — 싸고 일관됨.

KEEP/UPGRADE/OBSOLETE/NEW + confidence + evidence + 고신뢰 건 /cp 자동 핸드오프.

05 / 08 · KEY DECISIONS

왜 이렇게 설계했나

머신 독립 · 단순 안전 · false-obsolete 회피가 모든 분기의 기준이었다.

01

온디맨드 스킬 + 세션 알림 (cron 아님)

Lens는 여러 머신에 배포되는 플러그인. cron 대신 온디맨드 + staleness 알림이 머신 독립적이고 기존 /cu 패턴과 일치한다. 포터빌리티 우선.

02

레지스트리 = JSON

Claude(markdown) vs Codex(JSON) 분기. 사용자 "machine-readable" 명시 + 훅의 레지스트리-해시 staleness 트리거가 안정적 직렬화를 요구 → JSON 채택.

03

상태 = 프로젝트-로컬

전역이면 모든 프로젝트에서 nag. /cr은 lens 레포에서만 의미 있으므로 로컬 상태가 알림 스코프를 자연히 한정. 덤으로 해시 변경 재감사 신호.

04

fetch 실패 = UNKNOWN-default

추측으로 OBSOLETE를 찍는 게 최악(false-obsolete). 더 단순하고 안전한 UNKNOWN 표기. 버전-앵커 오프라인 판정은 과설계라 제거.

05

probe 신호 타입 허용

체인지로그는 능력을 다 안 알려준다 — 실행 중인 환경이 더 권위 있는 신호(Pre-mortem P1·P2). 로컬 확정 가능 신호는 signal_method: probe.

06

OBSOLETE 자동삭제 0

고신뢰 건도 삭제가 아니라 /cp task 핸드오프. 죽음 판정은 사람이. 모호하면 KEEP. 코드/스킬 자동삭제 금지.

06 / 08 · VALIDATION

이게 됐다는 증거

8개 검증 신호 + Pass 1 멀티에이전트 실증. 자동·수동 판정 혼합.

감사가 빠짐없이 분류하고, 비-KEEP엔 근거가 붙고, 알림 스코프가 lens 레포로 한정되는지 확인.

  1. 분류 완전성 + 근거 부착

    리포트 분류 행 수 = 레지스트리 항목 수(누락 0). 모든 비-KEEP 행에 공식 체인지로그 URL+버전(근거 없는 비-KEEP = 0).

  2. 핸드오프 + 3종 산출

    고신뢰 건이 docs/tasks/에 대응 /cp task로 생성. docs/history/<id>.md/.html + board 카드 노출.

  3. 알림 스코프 + 타이머 리셋

    creeta-lens=알림 출력 / 타 레포=미출력. stamp 후 lastAuditAt 갱신 → 재시작 시 알림 소멸.

  4. 안전장치 + degrade

    OBSOLETE 판정이 있어도 git status 변경분 = 문서·신규파일만. 네트워크 차단 시 비-KEEP을 UNKNOWN으로 표기, OBSOLETE 추측 0.

  5. Pass 1 실증 (2026-06-05)

    4차원 감사를 멀티에이전트로 1회 실행 → 2026-06-05-lens-modernization-audit.md(0 OBSOLETE / 2 KEEP / 9 THIN + 14 우선조치 + 신기능 0). 원자료 .lens/conv-mining/*.json.
