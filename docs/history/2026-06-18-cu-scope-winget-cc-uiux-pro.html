03 / 07 · PROBLEM

/cu가 플러그인 갱신에 두 번 걸려 넘어졌다

local scope 플러그인을 user scope로만 갱신하려다 실패하고, winget 출력은 cp949 디코드 크래시로 비어버려 gh를 "미감지"로 오탐했다.

Before

silent failure

context7 (local)not installed at scope user
playwright (local)not installed at scope user
winget reader threadUnicodeDecodeError 0xe2
gh detectionwinget 미감지—수동 안내 (오탐)

scope를 user로 가정 + winget UTF-8 박스문자를 cp949로 읽음 → 갱신 깨짐 · 출력 공백 · 오탐 연쇄.

After

실측 scope + UTF-8 디코딩

context7 (local)update --scope local · exit 0
playwright (local)projectPath를 cwd로 실행
winget reader threadutf-8 / errors=replace · 생존
gh detectioncan_auto=True (소스 감지)

installed_plugins.json의 실제 scope를 읽어 전달하고, 출력을 UTF-8로 강제 디코딩.

04 / 07 · KEY DECISIONS

왜 이렇게 고쳤나

가정 대신 실측, 소스 수정만으로 그치지 않고 전파까지.

01

scope를 실측해 전달

_plugin_scope_info()로 installed_plugins.json의 실제 scope를 읽어 --scope <scope>로 넘기고, local/project scope는 projectPath를 cwd로 실행. user scope만 가정하던 게 버그의 뿌리.

02

run()에 UTF-8 강제

encoding="utf-8", errors="replace" 추가. winget의 UTF-8 박스문자(0xe2…)에서 리더 스레드가 죽던 연쇄를 끊고, scan stderr 노이즈도 제거.

03

ui-ux-pro-max 재설치 안 함

이미 ~/.claude/skills/ui-ux-pro-max에 설치돼 있음을 확인. /cc Phase 1.3에 기존 "필수 실행 스킬" 메커니즘으로 의무 할당만 추가, 미설치 머신은 네이티브 베스트프랙티스로 graceful degrade.

04

bump + 핫미러 동시 전파

marketplace source.ref가 고정 태그라 소스 수정만으론 dormant. 3.19.0 → 3.20.0 bump·commit·tag·push로 정식 전파 + 활성 캐시(cache/CreetaCorp/lens/3.19.0)에 핫미러로 즉시 적용.
